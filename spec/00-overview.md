# Спецификация — 00. Обзор, глоссарий, источники

> Каждое содержательное утверждение заземляется ссылкой на источник:
> З1 — постановка задания, З2 — уточнения заказчика в интервью, З3 — внешние
> стандарты. Номера ADR см. в `decisions/ADR.md`.

## Цель

Клиент-серверная система «адресная книга организации» на Go: веб-интерфейс и
программный API; хранит имена и телефоны; ищет имена по телефону и телефоны по
имени; надёжно хранит много записей; движок хранения написан с нуля.

## Что система делает (поведение на верхнем уровне)

1. **Каталог сотрудников** — общая книга организации: добавить/изменить/удалить
   сотрудника, найти сотрудника по имени или по рабочему телефону. Телефон в
   каталоге глобально уникален (ADR-4).
2. **Приватные внешние книги** — у каждого сотрудника свой личный список контактов
   (имя + телефон): добавить/изменить/удалить, искать по имени или по номеру в
   своей книге. Внутри книги один телефон хранится один раз (ADR-4).
3. **Поиск** — регистронезависимый префиксный, в обе стороны (ADR-5).
4. **Отказоустойчивость** — три геораспределённых ДЦ; stale-чтение помечается (ADR-6).
5. **Атомарность** — множественные читатели/писатели, транзакционность (ADR-9).

### Объём как осознанное расширение З1 (contest, ADR-10/14)
Три геораспределённых ДЦ, ~20 млн записей, консенсус Raft и failover/fencing
**напрямую не вытекают из З1** («хранит имена и телефоны; ищет в обе стороны;
надёжно хранит много записей; написана с нуля на Go»). Это **осознанное авторское
расширение требований** по выбору заказчика «полномасштабный дизайн» (З2 →
ADR-10, консенсус → ADR-14): ядро — самописный движок имён и телефонов с поиском;
распределённый слой добавлен сверху для соответствия заявленной планке, а не по
прямому требованию исходной постановки. Без этого слоя система остаётся
полноценной; 3 ДЦ / Raft — добровольная надстройка уровня продакшн.

## Глоссарий

- **Движок хранения** — самописный слой персистентности (WAL, индексы,
  транзакции). Пишем с нуля (ADR-1).
- **Корпоративный каталог** — записи сотрудников, общие для организации (ADR-3).
- **Приватная книга** — личные внешние контакты сотрудника (ADR-3).
- **Запись** — единица хранения (сотрудник или приватный контакт).
- **Реплика / отставшая реплика** — копия данных в ДЦ, синхронизируемая
  асинхронно; может отставать по времени (ADR-6).
- **Tombstone** — маркер удаления, реплицируемый, чтобы удаление не «воскрешало»
  запись (ADR-9).
- **Staleness (отсталость)** — разница между состоянием реплики и primary;
  значение, которое показывается пользователю при чтении устаревших данных (ADR-6).
